# 移动端记账 Mock UI 中文化设计

## 背景

当前 `account-app-mobile` 的记账 Mock MVP 已完成主要流程，但界面仍存在较多英文文案与表达不一致的问题，主要集中在以下区域：

- 首页、明细页、统计页、我的页
- 新增交易页、编辑交易页
- 共享表单组件
- 空状态、副标题、按钮文案、状态标签

这会直接影响当前版本的可用性，也让后续真实业务接入时更难保持文案一致。

## 目标

本次调整将移动端记账 Mock UI 改为简洁自然的中文表达，并统一页面内的交互文案风格。

完成后应满足：

- 记账主流程中的用户可见英文基本清理完毕
- 同一概念在不同页面中使用一致说法
- 文案保持轻产品化，不刻意使用重财务术语
- 不引入完整 i18n 系统，仅整理当前中文默认文案

## 范围

本次修改包含：

- `app/(tabs)/index.tsx`
- `app/(tabs)/details.jsx`
- `app/(tabs)/statistics.jsx`
- `app/(tabs)/profile.jsx`
- `app/transaction/new.jsx`
- `app/transaction/[id].jsx`
- `components/accounting/transaction-form.jsx`
- `components/accounting/*` 中与记账页面直接相关的可见文案
- `constants/accounting-copy.js` 及相关中文文案映射

本次不包含：

- 多语言切换
- 系统级国际化框架接入
- 真实后端返回文案处理
- 与记账模块无关的全局页面文案改造

## 设计方案

### 方案 A：集中式中文化并顺手统一 UI 表达

做法：

- 优先把页面复用文案收进 `accountingCopy` 或现有常量
- 页面中零散的英文字符串同步清理
- 对按钮、空状态、字段名、分组副标题做一轮统一

优点：

- 后续新增页面不容易重新写出英文残留
- 改动边界清晰，复用性最好
- 能同时解决“翻译”和“表达不统一”两个问题

缺点：

- 比逐个字符串替换多一点整理工作

### 方案 B：只替换当前可见英文

做法：

- 哪里看到英文就在哪里直接替换

优点：

- 实现最快

缺点：

- 文案仍然分散
- 容易漏改
- 后续继续开发时容易再次出现英文

### 方案 C：直接引入完整 i18n

做法：

- 抽离所有文案并建立语言资源结构

优点：

- 结构最完整

缺点：

- 对当前 Mock MVP 过重
- 会扩大改动面，影响当前开发节奏

### 结论

采用方案 A。

它能在当前阶段以较小复杂度完成“中文化 + 文案收口”，符合当前项目节奏。

## 文案风格

整体风格采用“轻产品化中文”，强调自然、直接、简洁。

示例方向：

- `Add entry` -> `新增一笔`
- `Create transaction` -> `新增一笔`
- `Save changes` -> `保存修改`
- `Date and time` -> `时间`
- `Note` -> `备注`
- `Sync status` -> `同步状态`
- `No records for this month` -> `这个月还没有记录`
- `Switch months or add a new entry.` -> `切换月份，或先记上一笔。`

约束：

- 同一动作优先固定一种说法，例如统一使用“新增一笔”，不再与“创建交易”混用
- “交易”“记录”“一笔”按场景使用，但不制造同义词混乱
- 优先自然表达，不堆砌财务术语

## 页面级调整

### 首页

- 统一头部动作按钮为中文
- 最近记录区、副标题、同步摘要改为中文
- 账户区说明文案改为中文

### 明细页

- 页面副标题改为自然中文
- 空状态标题与说明改为中文
- 编辑、删除按钮保持短中文
- 按日分组的副标题保持简洁

### 统计页

- 分类区块标题、计数、副说明统一为中文
- 无数据时的说明改为中文

### 我的页

- 账户信息、账本信息、同步状态说明统一为中文
- 动作按钮与状态说明保持口语化

### 新增页 / 编辑页

- 页面标题使用中文
- 表单字段、按钮、错误提示全部改成中文
- 缺失记录时的空状态改为中文

## 组件级调整

### `transaction-form`

- 字段标签全部中文化
- 收入/支出、同步状态选项改为中文
- 保存按钮、删除按钮改为中文
- 校验错误提示改为中文

### 共用展示组件

- `EmptyState`
- `SectionHeader`
- `SyncBadge`
- `SyncSummaryRow`
- `TransactionListItem`

这些组件如有英文兜底文案，统一改为中文或改为由调用方传入。

## 数据与结构策略

- 复用现有 `accountingCopy` 作为主文案入口
- 对分类、月份等映射文案，沿用现有常量结构
- 页面内只保留极少量场景化短句；若在多个页面复用，则回收到常量文件

这样可以避免本次为了中文化引入新的复杂抽象。

## 错误处理

- 若编辑页通过 `id` 找不到记录，显示中文空状态并返回明细页
- 表单校验提示保持简短直接，例如：
  - `请输入大于 0 的金额`
  - `请选择分类`
  - `请选择账户`
  - `请输入正确的时间`

## 测试与验证

实现完成后执行：

- `npm.cmd run typecheck`
- `npm.cmd run lint`
- 记账相关测试：
  - `state/mock-app-state.test.js`
  - `components/accounting/transaction-form-support.test.js`
  - `components/accounting/home-details-utils.test.js`
  - `components/accounting/statistics-profile-support.test.js`
  - `components/accounting/helpers.test.js`

必要时补充针对中文文案映射或错误提示的轻量测试，但不为简单静态字符串过度测试。

## 实施边界

本次只处理“当前已接好的记账 Mock UI 中文化与表达统一”，不顺带改布局结构，不增加新功能，不重写设计系统。

## 完成标准

- 主要记账页面无明显英文残留
- 表单和空状态文案统一为中文
- 页面之间对同一动作或状态的说法一致
- `typecheck`、`lint`、相关测试保持通过
