# Transaction Entry Bottom Sheet Design

## Goal

将“新增一笔”页面从纵向表单改为分类优先的录入流：用户先选择分类，再通过底部滑出的输入面板填写金额、时间和备注，并使用自定义计算键盘完成金额录入。

## Confirmed Scope

- 页面顶部保留 `支出 / 收入 / 取消`
- 上半部分分类网格始终可见，可随时切换分类
- 分类激活态只改变图标圆形背景色，文字不做整块高亮
- 只有在用户选中分类后，底部输入面板才从页面底部滑出
- 底部输入面板包含金额显示区、时间入口、备注入口、计算键盘、`=`、`完成`
- 时间入口点击后继续使用现有日期选择弹层
- 金额支持完整表达式输入，例如 `12+3-1`
- `=` 只负责计算，不提交交易
- 如果表达式不完整，点击 `=` 清空金额，不新增交易
- `完成` 仅在当前金额已是纯结果且不含 `+` / `-` 时可点击并提交

## UI Decisions

### 1. Page Layout

- 页面改为两段式结构：
  - 顶部绿色栏：类型切换和取消动作
  - 主体上半部分：分类网格
  - 主体下半部分：底部滑出输入面板
- 上半部分分类区不因面板出现而被替换；面板覆盖在下方区域上方
- 底部面板使用圆角顶边，和主体形成抽屉式关系

### 2. Category Selection

- 分类卡片保持现有网格密度，但视觉从“整块 pill”调整为“图标圆底 + 文本”
- 未激活状态：
  - 图标圆底使用浅中性色
  - 文本使用普通正文色
- 激活状态：
  - 只有图标圆底切为应用绿色
  - 图标切为反差更高的前景色
  - 文本保持普通样式，不增加底色或描边
- 点击其他分类时，不收起面板，只更新当前 `categoryId`

### 3. Bottom Sheet Content

- 未选分类时：不显示底部面板
- 已选分类时：显示底部面板，并默认聚焦金额录入流
- 面板内容顺序：
  1. 金额显示区
  2. 时间入口
  3. 备注入口
  4. 自定义计算键盘
- 时间和备注使用轻量信息行，而不是完整文本表单块，减少垂直占用

### 4. Time And Note

- 时间入口显示当前草稿日期时间摘要，点击后继续打开现有日期选择器
- 日期选择确认后，仅更新表单草稿中的日期时间，不影响当前金额表达式
- 备注入口显示“点击填写备注”占位提示；点击后进入备注输入
- 备注保留现有草稿字段和提交流程

## Expression And Keypad Behavior

### 1. Input Model

- 金额不再依赖系统 `TextInput` 直接输入
- 新增受控表达式状态，至少包含：
  - `expression`: 当前显示字符串
  - `resolvedAmountInput`: 已结算后的金额字符串
  - `canSubmit`: 当前是否允许点击 `完成`
- 自定义键盘是金额输入的唯一入口

### 2. Allowed Keys

- 数字 `0-9`
- 小数点 `.`
- 运算符 `+`、`-`
- 退格 `⌫`
- 计算键 `=`
- 提交键 `完成`

### 3. Expression Rules

- 允许输入完整表达式，例如：
  - `12+3`
  - `12+3-1`
  - `0.5+1.25`
- 不允许提交包含未结算运算符的字符串
- 视为不完整表达式的例子：
  - 空字符串
  - `12+`
  - `12-`
  - `12..3`
- 点击 `=` 时：
  - 如果表达式完整，计算结果并用纯金额结果替换显示内容
  - 如果表达式不完整，清空金额显示区，不提交交易
- `完成` 仅在以下条件同时满足时启用：
  - 当前金额显示非空
  - 当前显示值不包含 `+` / `-`
  - 当前金额可被解析为有效的正数金额

### 4. Submit Flow

- 点击 `完成` 后，沿用现有交易提交逻辑
- 提交 payload 继续走已有的金额分、分类、账户、时间、备注拼装
- 如果金额尚未结算成纯结果，则不允许进入提交分支

## Architecture

### 1. Transaction Form Refactor

- 保留 `TransactionForm` 作为页面主组件，但重组内部布局
- 将原有纵向字段块改为：
  - 头部类型切换
  - 分类网格
  - 条件渲染的底部面板
- 原有日期弹层逻辑尽量保留
- 原有 `draft` 结构保留，用于最终提交；金额显示逻辑由表达式状态层驱动

### 2. New Support Module

- 新增金额表达式支持模块，职责包括：
  - 初始化表达式状态
  - 处理按键输入
  - 判断表达式是否完整
  - 计算表达式结果
  - 生成可提交金额字符串
- 该模块保持纯函数，便于单测覆盖

### 3. Draft Synchronization

- 表达式计算出纯结果后，再同步回 `draft.amountInput`
- 表达式未结算时，不写入可提交金额
- 切换分类时：
  - 保留当前表达式和已输入备注、时间
  - 仅更新 `draft.categoryId`

## Error Handling

- 不完整表达式点击 `=`：清空金额显示，不弹错误提示，不提交
- 无分类时：不展示面板，自然无法提交
- 金额为空或非正数时：`完成` 保持禁用
- 日期弹层取消时：保持原草稿值，不影响表达式

## Testing

- 为金额表达式支持模块补单测，覆盖：
  - 数字与小数输入
  - `+` / `-` 连续运算
  - 表达式完整性判断
  - `=` 计算成功
  - `=` 在不完整表达式下清空
  - 退格行为
  - `完成` 启用条件
- 为 `TransactionForm` 行为补 focused 测试，至少覆盖：
  - 选中分类前不显示面板
  - 选中分类后显示面板
  - 切换分类时面板保持展开
  - 仅在纯结果状态下允许提交
